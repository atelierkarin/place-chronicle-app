# Place Chronicle 実装計画

> **作業者向け:** タスクごとに実装・検証・レビューする。完了した項目だけ `- [x]` に変更する。

**目的:** 個人の訪問記録を場所・日付・写真から安全に記録し、地図・時系列・場所別に見返せるMVPを作る。

**構成:** `apps/web` にReact + TypeScript + Vite、`apps/api` にHono + TypeScriptを置くnpm workspaces構成を想定する。PostgreSQLにPlace、Visit、Photoのメタデータを保存し、写真原本とサムネイルはローカルファイルへ保存する。開発中のDBだけをDocker Composeで起動する。

**技術:** Node.js 24 LTS、npm、React、Vite、Hono、PostgreSQL 17、MapLibre GL JS、Vitest、Playwright。各ライブラリの具体的なバージョンは導入時に互換性を確認してロックファイルへ固定する。

**設計書:** [基本設計書 v0.1](place-chronicle-design-v0.1.md)。同文書は方向性が確定した初期構想であり、詳細なAPI・保存仕様は本計画のM0で決定する。

## 全体に適用する条件

- 初期はローカルの個人利用。外部公開、認証なしのネットワーク公開、SNS機能は対象外。
- Place 1:N Visit、Visit 1:N Photo。位置座標はPlaceに属し、訪問日時はタイムゾーン付きで保存する。
- 実際の訪問履歴と写真はリポジトリに追加しない。テストでは架空データを使う。
- 原本画像を保存し、サムネイルは別管理する。バックアップはメタデータと原本画像を含み、復元まで検証する。
- M0/M1/M2の各終了時に、アプリを起動できる状態とREADMEの次の一手を維持する。

## 未決事項と決定の時点

| 項目 | 現時点の方針 | 決定する時点 |
|---|---|---|
| PostgreSQLとSQLite | PostgreSQL 17を採用。ローカル起動・マイグレーション・テストを確認済み | M0で決定 |
| ORM・マイグレーションツール | ORMなし。最初はSQLと小さな適用スクリプトを使用 | M0で決定 |
| 写真の制限値と画像処理ライブラリ | 1枚15 MiB、1訪問20枚、1回10枚、JPEG/PNG/WebP。画像処理ライブラリはM1で選ぶ | 制限値はM0で決定 |

## 調査根拠（2026-10-11確認）

- [Vite公式ガイド](https://vite.dev/guide/)：現行版はNode.js 20.19+または22.12+が必要。調査時点の旧環境20.16.0では不足していた。
- [Node.jsリリース一覧](https://nodejs.org/en/about/previous-releases)：Node.js 24はLTS、20はサポート終了。24を開発基準に採用。
- [HonoのNode.jsガイド](https://hono.dev/docs/getting-started/nodejs)：Node.jsアダプターで実行できる。
- [PostgreSQL公式Dockerイメージ](https://hub.docker.com/_/postgres)：17タグと初期化環境変数、データボリュームの扱いを確認。
- [Docker Composeの起動順ガイド](https://docs.docker.com/compose/how-tos/startup-order)：DBの準備完了判定にはヘルスチェックを用いる。
- [MapLibre GL JS](https://maplibre.org/maplibre-gl-js/docs/)と[OpenStreetMapタイル利用規約](https://operations.osmfoundation.org/policies/tiles/)：描画ライブラリとタイル提供元は別に選ぶ。タイルの帰属表示・負荷・キャッシュ規則に注意する。
